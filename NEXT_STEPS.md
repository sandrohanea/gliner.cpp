# Next steps

## Implemented

- **GGUF-only text classification:** C++ schema construction, Unicode word splitting/lowercasing, NFC/Metaspace Unigram tokenization, marker routing, DeBERTa embeddings and every encoder layer, and contextual classification.
- **Model-format validation:** application format version 2 preserves all tensors and carries required encoder/tokenizer behavior. Legacy files remain head-only; unsupported or incomplete new models fail explicitly.
- **C API and CLI:** `gliner_classify_text`, per-state diagnostics, `--text`/`--text-file`, prompts, descriptions, word truncation and explicit token limits. The precomputed `--states` path is retained.
- **Joint question batching:** `gliner_classify_text_batch` accepts one text and ordered tasks; CLI repeated `--task` groups expose per-question labels, prompts, descriptions and decoding. The model is loaded once, the text token sequence is included once, and all questions share one encoder pass. Task score ranges preserve grouping, while single-task behavior/output remains compatible. Joint scores can differ from independent calls because schemas attend to one another.
- **Basic decoding:** exclusive softmax/argmax, independent sigmoid thresholds and probability temperature, with unmodified raw logits.
- **Parity:** committed synthetic token/hidden-state/logit fixtures and optional live checks against the real F32 Decide checkpoint. Eight single-task and five joint-schema cases match token IDs, routing and task offsets exactly. Maximum observed absolute hidden-state error is below `3e-5` for single tasks and `1e-4` for joint schemas across all 24 layers. A C callback-count test verifies one encoder traversal per batch. See README for revisions, tolerances and reproduction commands.
- **Model input APIs:** file, borrowed byte buffer and whisper-style sequential stream loaders (`read`/`eof`/`close`). Stream loading handles short reads without seeking, copying the entire checkpoint or creating a temporary file. Accepted loaders close exactly once on success/failure; input memory can be released after initialization.
- **Build-time backends (GPU paths experimental):** `GGML_CUDA`/`GGML_METAL` choose a fixed execution backend; both off selects CPU. No runtime backend/device selection parameters are exposed. Weights and state scratch use the compiled backend's first available device, GPU matmuls request F32 accumulation, and unsupported operations fail explicitly without silent fallback. Read-only `--build-info`, `--inspect` and `--debug` report build/runtime identity.

## Remaining

1. **CUDA hardware validation and optimization (priority).** Build with `GGML_CUDA=ON`; run the C API, synthetic F32/F16 and real F32 per-layer parity suites on NVIDIA hardware on Windows and Linux. Verify disentangled attention gathers, exact GELU, normalization, repeated state reuse and multiple states sharing device weights. Record GPU/driver/toolkit versions, cold-load latency, steady-state latency and peak VRAM; test allocation failures and longer sequences. Establish real-checkpoint F16 error budgets before enabling reduced-precision optimizations or claiming validated CUDA support.
2. **Metal hardware validation and optimization (priority).** Build with `GGML_METAL=ON` on Apple Silicon; validate shader deployment and every encoder layer against Python and CPU GGML. Exercise F32/F16 storage, attention gathers, normalization, state reuse and unified-memory pressure. Benchmark representative M-series machines and document minimum supported macOS/toolchain versions before claiming validated Metal support.
3. **Backend memory management and coverage.** Evaluate build-configured GGML scheduler-based CPU fallback/partial offload with explicit placement reporting when a device lacks an op or sufficient memory. Keep backend selection at build time and avoid silent fallback. Evaluate pinned transfers for CUDA and unified-memory placement for Metal; consider Vulkan and other GGML backends only after CUDA/Metal acceptance gates. Multi-GPU splitting is a separate future milestone.
4. **Broader parity coverage.** Add a held-out application corpus, longer contexts, more adversarial Unicode/schema cases and real-checkpoint F16 tests. Preserve intermediate-layer checks when changing kernels. Synthetic F16 coverage is not a substitute for real-model F16 validation.
5. **Upstream schema/decision surface.** Add few-shot examples, explicit description ordering independent of label order, cross-task constraints and upstream exact/beam decoding. Multiple tasks per encoder pass are implemented; constrained decisions are not. Match upstream decisions and tie-breaking before claiming full Python API parity.
6. **Long documents and multi-document batching.** Add documented chunking/aggregation policies, variable-length document batches and attention masks. Current joint batching shares one text across questions, not multiple independent documents. The aggregate schema-plus-text token limit deliberately fails rather than silently dropping or splitting tasks.
7. **Performance.** Benchmark cold loading and steady-state CPU inference, then reduce attention-index memory, precompute immutable relative projections, introduce memory mapping and cache schema tokenization. Use CPU/CUDA/Metal parity gates when changing graph layouts or kernels.
8. **Quantization and packaging.** Establish separate error budgets for F16 and quantized weights; retain original tensors unless a new format version explicitly documents pruning. Add install/export targets and platform CI with installed, local and fetched GGML, plus NVIDIA CUDA and Apple Silicon Metal hardware lanes.

CUDA and Metal are not yet hardware-validated: the current development host is Windows without an exposed NVIDIA GPU or CUDA toolkit. Run CTest in separate CPU/CUDA/Metal build directories; each suite asserts its binary's compiled backend and unavailable GPU devices fail rather than skip. CPU remains the verified reference inference path.

NER/span/JSON extraction and alternate encoders are not part of the current classification runtime, even though their checkpoint tensors are preserved.
